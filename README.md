# 電子名片（NFC／QR）

> 上線：2026-09-24 · 永久入口 https://ohyadaisy.github.io/ · 名片頁 https://ohyadaisy.github.io/card/ · repo `ohyadaisy/ohyadaisy.github.io`

永久入口轉址層 + 純靜態名片頁。**沒有建置步驟、沒有執行期依賴、不綁任何平台**，
`git push` 就是發布。

第一次使用請先讀 **`START-HERE.md`**，上線流程在 **`SETUP.md`**。
這一頁是**上線之後**的維護說明。

---

## 架構：為什麼要多一層轉址

```
NFC 貼紙 / 印出去的 QR
        ↓
https://<帳號>.github.io/        ← 永久入口（本 repo 根目錄的 index.html）
        ↓
https://<帳號>.github.io/card/   ← 名片頁本體（想換就換）
```

貼紙一旦貼出去、QR 一旦印上紙本名片，網址就凍結了。
中間隔一層自己控制的網址之後，**換內容、換平台、換網域都只要改轉址頁一行，
所有已經發出去的名片與貼紙全部自動生效**，不需要重寫 NFC、不需要重印 QR。

轉址用三重保險：`<meta refresh>`（不依賴 JS）→ `location.replace()`
（不留歷史紀錄，按上一頁不會被彈回）→ 畫面上的手動按鈕（前兩者被擋時的退路）。
查詢字串與錨點會帶到目標站，日後可做來源追蹤（NFC 寫 `?src=nfc`、紙本寫 `?src=card`）。

## 日常維護

### 改文字或聯絡資訊
1. 改 `card/config.js`（唯一真相）。
2. 中文內容同步改一份到 `card/index.html`
   （中文直接寫在 HTML 裡，JS 失效時名片仍然可讀）。
3. 改了姓名／電話／Email／地址 → `npm run vcf` 重新產生通訊錄檔。
4. `npm test` 全過。
5. `git push`，約 1 分鐘生效。

### 換 LINE QR Code
換圖路徑是 `card/line-qr.jpg`，並同步改 `config.js` 的 LINE 網址。**三條規則**：
1. 四周留白至少 **4 個模組**（黑色定位點方塊邊長 = 7 個模組，由此推算單一模組寬）。
2. 不要重新取樣。要加留白就把原圖**以原解析度貼到更大的白底**上，模組邊緣才不會糊。
3. 圖片本身不可加 `border-radius`——QR 的角落就是定位點，圓角會啃掉它。
   視覺圓角由外層白框負責，只修到留白。

換完用解碼器實測，再 `npm test`（有兩項測試在守這件事）。

### 改了聯絡資料之後，紙本名片圖也要重掃
`card-front-zh.*` 與 `card-back-en.*` 是點陣檔，**不會跟著 `config.js` 變**。
`config.js` 的 `assets.paperCard.printed` 記著圖上實際印的資料，`npm test` 會比對——
改了職稱／電話／Email／地址卻沒重掃名片，測試會失敗並指出要更新哪裡。

重做時：掃描正反面 → 裁到卡片實際邊界（掃描器會留灰邊）→
匯出 1057×634 的 WebP（quality 82）與 JPEG（quality 88）→ 覆蓋四個檔 →
更新 `printed` → `npm test`。

### 換名片頁本體（搬到別的平台）
改 `index.html` 兩處，**必須一致**：`<meta http-equiv="refresh">` 的網址、
JS 裡的 `var TARGET`（順手更新 `<link rel="canonical">`）。
NFC 與 QR 一律不動。

## 已知的平台限制（查清楚後接受的，不要再嘗試繞過）

**Android 沒有任何網頁 API 能直接開啟「新增聯絡人」。**
`intent://` 實測完全無反應，Blob 導航、JS 導航、靜態 `.vcf` 導航一律變成下載。
這不是寫法問題。所以 Android 走下載，並在頁面上給明顯的成功回饋
（綠色卡片 + 自動捲入視野 + 一顆「開啟檔案並加入聯絡人」按鈕）。
網頁也**無法**叫出 Chrome 自己的「是否要下載」對話框，那是瀏覽器端設定。

**Android Chrome 不允許分享 `text/vcard`。**
`canShare({files})` 會回 false 或 `share()` 直接丟例外。
iOS Safari 允許，所以同一段程式碼在 iPhone 順暢、在 Android 必然失敗——
交付邏輯因此做成**逐級降級**（`card/save-strategy.js`），任何一層失敗都往下一層走，
最後一層永遠是可長按另存的連結，不讓使用者卡在死路。

**iPhone 感應 NFC 後必須點一次通知橫幅。** Apple 的安全設計，無法繞過。
iPhone 7／8／X 不支援背景感應，需從控制中心加入「NFC 標籤讀取器」手動觸發。

## 測試在守什麼

`npm test`（34 項）**測行為，不測字串**。曾經有一版 8 項測試全過卻讓
Android 的 bug 上線，因為那些測試比對的是原始碼字串，等於把錯誤行為鎖成正確答案。

幾個關鍵的守門項：
- **交付路徑**：每種裝置在分享失敗後都還有後續步驟，沒有死路
- **填了相識資訊就不得走靜態 `.vcf`**——那個檔帶不動時間／場合／GPS，
  使用者辛苦填的資料會默默消失
- **靜態 `.vcf` 與 `config.js` 同步**——改了聯絡資料忘記重新產生會被擋
- **紙本名片圖上印的資料與 `config.js` 同步**——同上，圖不會自己變
- **翻卡一次只有一面在排版中**——真機 regression：兩面同時落進排版會疊成一長條被拉變形
- **版面不得交給 3D 決定**：`preserve-3d` + 絕對定位堆疊在真機上壞過一次。
  動畫是疊在版面之上的裝飾，動畫失效只該變成直接切換，版面不受影響
- **QR 不得加圓角、留白要達標**
- **三語齊備**，新增內容時漏翻會被擋

## 量測窄螢幕版面時的注意事項

headless Chromium 的 `--window-size` **不會設定版面視窗**——
頁面可能以 485px 排版，而截圖只取了左邊 390px 那一段，於是看到不存在的「被切掉」。
要量窄螢幕，請用固定寬度的 iframe 驅動頁面並讀 DOM 數字
（排版中的元素數、水平溢出、元素右緣座標），不要只看截圖。

本包的 `npm start` 是零依賴的本機預覽伺服器，可搭配瀏覽器的裝置模擬使用。
